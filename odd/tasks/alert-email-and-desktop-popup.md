# Alert email delivery and desktop popup with sound
Objective: notify target-alert crossings by SMTP email and by an in-app popup with sound. Branch: dev. Delivery: work units on dev (no PR requested). Test runners: backend `python -m pytest backend/tests -q`, frontend `npx vitest run`.

## Specs
- S1: "hay que trabajar en el envio a un correo. como lo hacemos?" — channel chosen by the user: "SMTP en el stack (recomendado)". Send one email per new crossing using `smtplib` (stdlib), with host, port, user, password, TLS flag and timeout read from environment variables injected through Compose and documented in `.env.example`. No new runtime dependency.
- S2: "tambien un popup con sonido" — show an in-app popup with sound when a crossing fires. The popup is global (rendered from `WorkspaceShell`, works on any workspace), deduplicated by event id, and uses the `QuickOrderCard` visual tokens. The sound is a short WebAudio beep with an enable/disable toggle in Configuración persisted in `localStorage`; if the browser blocks audio, degrade to a silent toast.
- S3: Email recipient is `AUTH_EMAIL` from the environment, with optional `ALERT_EMAIL_TO` override for a different destination. (Assumption: the background scheduler has no request context, so the authenticated user's address cannot be resolved at send time from the session.)
- S4: Never email the same crossing twice. Add a nullable `emailed_at` column to `alert_event_records` through an Alembic migration; list unemailed events and mark each one after a successful send. Existing rows are backfilled as already emailed so a deployment does not replay history.
- S5: An SMTP failure is contained: log it, leave the event unmarked so the next scheduler tick retries, and never break the evaluation loop. A configured notifier is optional; with no SMTP host the notifier is a no-op and only the in-app popup fires.
- S6: The popup polls `GET /api/v1/alerts/events` on an interval, seeds the "seen" set from the first load so pre-existing events do not pop up, and surfaces new ids as toasts. Closing a toast does not acknowledge the event; acknowledgment stays an explicit action in the alerts workspace.
- S7: Documentation and configuration are updated in both languages: `.env.example`, `compose.yaml` (and the dev/local variants if they define backend env), `README.md`, `CHANGELOG.md` and `CHANGELOG_es.md`.

SMTP failures are isolated and retried; with `SMTP_HOST` empty the notifier is inert.
