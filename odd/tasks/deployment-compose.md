# deployment-compose

Objective: define the base deployment and the dev override for the current stack — frontend SPA on Nginx, backend on Uvicorn and PostgreSQL — so `docker compose up` brings up a healthy stack with a database that is never published, and `compose.dev.yaml` brings the same three services up with hot reload and isolated data.
Branch: `dev`. Delivery strategy: `ask-on-risk` (the measurement and decision go in the Log).
Test runner: `python -m pytest backend/tests/test_deployment_config.py -q`, full suite `python -m pytest backend/tests -q`, frontend `npm test` in `frontend/`.

## Specs

- **S1** — `docker compose config` resolves the base stack and the dev override with the variables from `.env.example`, and no service publishes PostgreSQL. The plan's contract: "PostgreSQL con `expose` (no `ports`), volumen `postgres_data`, healthcheck; backend depende del healthcheck y aplica Alembic antes de Uvicorn".
- **S2** — The base stack gains a `frontend` service that serves the SPA over Nginx and proxies `/api` to the backend, on a published `${WEB_PORT}`. The plan's contract: "frontend sirve la SPA y proxya `/api`".
- **S3** — `compose.dev.yaml` is an override that adds hot reload for the backend (Uvicorn `--reload` over the mounted source) and a Vite dev server for the frontend, with data isolated from the base stack. The plan's contract: "override con hot reload (backend/uvicorn reload, Vite dev server) y datos de prueba aislados".
- **S4** — Credentials and configuration reach the containers only through environment variables (`POSTGRES_*`, `VITE_API_BASE_URL`), never through a file copied into an image. The plan's contract: "Secretos sólo por variables de entorno (`POSTGRES_*`, `VITE_API_BASE_URL`); nunca en la imagen".
- **S5** — `.env.example` declares every variable the compose files interpolate, so a fresh clone can run with an explicit value for each. The plan's TDD step: "tests estáticos que validan ... que `.env.example` declara las variables".
- **S6** — The build context never carries secrets or local state into an image: `.dockerignore` keeps `.env`, `finance.db`, `verify/`, `node_modules`, build output and the git directory out of both images.
- **S7** — `frontend/nginx.conf` serves the SPA for client-side routes and proxies `/api/` to the backend without duplicating the prefix, and the frontend image is a multi-stage build (Node build stage, Nginx runtime stage) with the API base URL injected as a build argument. Amended after the smoke run: it also proxies `/health` and `/ready`, because the SPA fallback otherwise answers 200 with `index.html` on those paths and a probe reading the published origin gets a healthy signal while the database is down (L8).
- **S8** — With PostgreSQL down the backend still answers `/health` while `/ready` returns 503, and the SPA shows a usable error state. This is the plan's "Fallo de PostgreSQL → `/ready` 503 y el frontend muestra estado de error usable"; the frontend side is already implemented in `frontend/src/components/AsyncStates.tsx` and its feature tests, so this task verifies it rather than adding it.
- **S9** — `README.md` documents both flows (base stack and dev override), the required variables and the guarantee that the database is not published. The full README refresh stays in 7.1; this task documents the deployment it creates.
- **S10** — Deployment configuration is guarded by `backend/tests/test_deployment_config.py`, static assertions over the files themselves, so a later edit that publishes the database, drops the healthcheck dependency, removes the dev override or stops declaring a variable fails the suite.
- **S11** — Scope decision recorded: the Vite dev server reaches the backend through its own proxy (dev-only `server.proxy` in `vite.config.ts`) instead of adding CORS to the API, because the API has no CORS middleware and a single-origin dev flow mirrors how Nginx serves the same SPA in the base stack. See L4.
- **S12** — No regression: the full backend suite, `ruff`, `mypy`, the frontend suite, lint and build stay green, and no existing endpoint or documented command changes behavior.
