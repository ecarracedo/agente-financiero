# review-debt-cleanup

Objective: clear every non-blocking advisory raised by the Phase 5 native RDD reviews so `dev` carries no review debt before Phase 6.
Branch: `dev` (work-unit commits land here). Delivery strategy: `ask-on-risk` — the running authored-line count is ~728 (additions + deletions, excluding the user's pre-existing `AGENTS.md` change and this document), above the ~400 heuristic, so delivery slicing is raised with the user instead of being applied silently.
Test runners: backend `python -m pytest backend/tests -q`; frontend `cd frontend && npm test`.

## Specs

Each spec quotes the review finding id, its exact location and severity. All are advisories from the reliability lens; none blocked the reviews. `FIX` marks a defect, `OUTCOME` records what actually happened when the spec was executed.

- **S1** — `R3-split-nan-ratio` (`frontend/src/features/tools/split/SplitWorkspace.tsx:34-36`, WARNING). A non-numeric ratio parses to NaN, which the component deliberately maps to 0 so the backend rejects it with a 422. Pinned by tests, both forward and reverse ratios.
- **S2** — `R3-bib-year-nan` (`frontend/src/features/bibliography/BibliographyWorkspace.tsx:45`, WARNING). FIX: a non-numeric year was serialized as `null` and sent silently. The year is now set only when the parsed value is finite. RED: `expected … to not have property "year"`.
- **S3** — `R3-empty-required` (`frontend/src/features/bibliography/BibliographyWorkspace.tsx:62-63`, WARNING). FIX: a blank title or author returned silently. It now surfaces `Title and author are required.` and sends nothing. RED: `Unable to find role="alert"`.
- **S4** — `R3-mock-weak-path` (`frontend/src/features/tools/split/SplitWorkspace.test.tsx:7-11`, SUGGESTION). The API mock pinned no payload shape. A test now asserts exactly one request with the exact payload keys.
- **S5** — `R3-adapter-undated-skip-untested` (`backend/app/adapters/market_data.py:82-84`, WARNING). The branch that skips entries whose index is unparseable as a date is now covered: a mixed payload keeps only the valid point.
- **S6** — `R3-duplicate-dates-untested` (`backend/app/domain/analysis.py:88-90`, SUGGESTION). Sorting is by date only, so duplicate dates are kept in stable order and count toward moving-average windows. Pinned by a characterization test.
- **S7** — `R3-refresh-untested` (`frontend/src/App.test.tsx:50-63`, WARNING). `App` fills `refreshToken` from `portfolioVersion`. A shell test covers the end-to-end refetch, and a component test pins the wiring itself: a changed `refreshToken` refetches, an unchanged one does not. The shell test alone could not isolate the bump because `App` unmounts inactive workspaces.
- **S8** — `R3-stale-history` (`frontend/src/features/transactions/useTransactionHistory.ts:55-77`, WARNING). OUTCOME — not a defect. Four scenarios were run and all pass: an error cleared by a later successful refetch of the same criteria; a new error surfaced after a success; the previously loaded rows dropped when a refetch fails; and a superseded fetch not overwriting the current criteria. The hook is unchanged and the behavior is pinned by the new `useTransactionHistory.test.ts`.
- **S9** — `R3-selectors` (`frontend/src/features/portfolio/PortfolioWorkspace.test.tsx:70-76`, SUGGESTION). Collision-prone bare-text assertions replaced with scoped `getByRole('cell')` plus `within(row)` queries.
- **S10** — `R3-ticker-select-stale` (`frontend/src/features/market/MarketWorkspace.tsx:49-52`, WARNING). Two halves. (a) DISPLAY FIX: the select had no option for a searched ticker outside the catalog, so it kept displaying the first catalog entry while the chart and the analysis already belonged to the searched ticker. The active out-of-catalog ticker is now an option. RED: `Expected NVDA / Received AAPL`. The reviewer's suggested remedy applied to selection itself was REJECTED: validating the selection against the catalog would break the documented free-text ticker search, so out-of-catalog selection stays deliberate and is pinned by a test. (b) FIX (user decision): selecting a ticker absent from both portfolio and wishlist rendered the target-alert panel, and saving an alert there always failed with 404 `wishlist item does not exist` (`backend/app/application/alerts.py:75-76`). The user's decision: "La alerta tiene que ser para un ticker que tenes en el portfolio o en la wishlist. Si agregas una alerta que no esta en ambas, agregarla por defecto a whislist. Porque entiendo que estas queriendo saber cuando un activo llegue a un precio". Configured alerts now add a missing ticker to the wishlist inside the same unit of work, so the panel's save succeeds. RED: `ValueError` at `alerts.py:76` and HTTP 404 instead of 200. Pinned at the application level and through the HTTP endpoint.
- **S11** — `R3-alert-validation-gaps` (`frontend/src/features/alerts/AlertsPanel.tsx:46-66`, WARNING). FIX: an empty target price was sent raw. It now surfaces `Target price is required.` and sends nothing. RED: `Unable to find role="alert"`.
- **S12** — `R3-weak-assertions` (`frontend/src/features/market/MarketChart.test.tsx:37-62`, SUGGESTION). All recharts CSS-class assertions replaced with accessible queries. Recharts exposes no accessible role for marker symbols, so symbol count is no longer asserted; the marker list is.
- **S13** — `R3-no-loading-state-test` (`frontend/src/App.test.tsx:21-26`, WARNING). The intermediate checking state is now covered: pending, then settled.
- **S14** — `R3-http-edge-cases` (`frontend/src/api/http.test.ts:60-103`, WARNING). 204, a non-JSON body on an error status, and a trailing-slash base URL are now covered. Two observations were recorded and NOT fixed, because the finding was coverage: a trailing-slash base URL produces a double slash (pinned as current behavior), and a 2xx response with a non-JSON body reaches `response.json()` unwrapped and would throw a raw `SyntaxError`.
- **S15** — `R3-missing-openapi-artifacts` (`frontend/package.json:11`, WARNING). NO-OP: verified artifact of the review split — `frontend/openapi.json` and `frontend/src/api/types.ts` both exist and the `generate:api` scripts reference them correctly.
- **S16** — `R3-no-ci-config` (`frontend/vitest.config.ts:5-12`, SUGGESTION). TOOLING: `.github/workflows/` existed but empty. A workflow now runs backend pytest and the frontend lint/build/test/drift checks. Cannot be executed locally — GitHub Actions runs it on push.
- **S17** — `R3-no-drift-check` (`frontend/src/api/types.ts:1-4`, WARNING). TOOLING: two checks added. `npm run check:api-drift` regenerates the types from `openapi.json` into a temp file and fails on any byte difference; `backend/tests/test_openapi_snapshot.py` fails when the snapshot drifts from the live application. Precondition verified green (17 paths, 24 schemas, `info.version` 0.1.0, OpenAPI 3.1.0) and the drift check was verified to exit 1 on injected drift.
- **S18** — `R3-loose-schema` (`frontend/openapi.json:1181-1195`, SUGGESTION). NO-OP: loose but usable, no consumer broken; tightening it is a design change, not debt.
